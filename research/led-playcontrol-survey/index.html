LED media server · frame sync · 3D mapping

一台机器带不动的屏幕，
怎么同步地播

超分辨 LED 不是「多开几路 HDMI」。单机 GPU 与解码带宽撑不住时，行业的解法是多机多显卡切片输出。真正难的是两件事：相邻箱体必须在同一帧、同一扫出相位上会合；球形和折面必须把平面纹理贴到真实几何上。下面按同一套坐标系，对照国内外播控软件怎么做这两件事。

01

问题定义

超 8K / 16K 点对点、超长卷、球形屏，单台工作站的解码、PCIe、DP 口数量和 Mosaic 桌面都会先撞墙。多机是扩空间；同步和几何才是扩完之后还像一块屏。

单机为什么不够

  1. 解码：H.264/H.265 超 8K@60 或无损序列帧，一张消费级卡吃不满带宽。
  2. 输出：一块 GPU 的 DP 口数量有上限；Mosaic 把多口拼成超大桌面，驱动与 EDID 变得脆弱。
  3. 几何：球形、环幕、折面不是矩形裁切，需要按模组 UV 或离轴投影生成切片。
  4. 链路：LED 处理器、摄像机、音频还要和服务器锁在同一基准上，否则只锁 PC 仍会撕。

常见失败不是「机器不够快」，而是只做了空间切片，没做帧身份 + 扫出相位，或只做了 NTP 对时，就把相邻箱体交给 LED 发送卡「自己对齐」。

公开资料里已经写清的边界

WATCHOUT：NTP 把节点钟拉到约 1 ms，但 GPU 仍各自扫出；亚帧相位在 LED 处理器上看就是撕缝。Hardware Sync Group 把计时源切到同步卡帧计数。

disguise：Genlock 锁集群与摄像机/LED 设备；Framelock 只锁同一台服务器的多头。IP 输出时 PTP 与 NTP 不是一回事。

国内产品大量使用「帧同步级联」一词。能核到卡型的，目前公开页里 HiRender S3 写明需要 Quadro Sync II，Kommander F30 规格书列出同步卡。应用层报文仍属 C；物理层已经能分开：KFS / F30 可落到 NVIDIA Frame Lock CAT5，GrandShow Sync 推断走以太网，Kompass Lora 是无线 LoRa 对时。

LTC 接收异常数据

LTC 是 L1。坏帧不能直接去跟时间线。对照 WATCHOUT LTC Bridge 计数器、ETC 飞轮、约 100 ms 超时。

NTP 把系统钟对齐到约一毫秒，但并不对齐 GPU 输出。各节点仍按自己的钟扫出，相位差一个亚帧。这个差在普通投影上几乎看不见，在已 Genlock 的 LED 处理器上会变成整帧错位和箱体接缝撕裂。Hardware Sync Group 用同步卡帧计数替换 NTP 作为计时源。

03

球形与异形屏：3D 切片流水线

2D 多边形切片适合矩形拼缝和折角。球、环、自由曲面更合适的源是三维模型。几何映射和多机同步是两条支线。曲面、天空盒和立体视差拆在下一章，这里仍只讲切片流水线。

谁走 3D 主路径

GrandMapping：预设模型 / AI 推断屏体 → 调观察视角自动切片 → 导入卡莱特发送卡连接关系。公开页把球形、弧形写成目标场景。

hecoos：Studio 三维预演（灯、屏、机械、摄像机）无缝交给 Server。设计端与播放端分离，是国内最接近 disguise 工作流的结构。

disguise / PIXERA：屏是舞台对象。VP 还要求摄像机、跟踪、LED 处理器与服务器同 genlock。

VMEET：自定义模型、球幕 / 隧道 / CAVE、任意多边形重组，作为国内球幕对照。

谁停在 2D 快路径

Kommander / GrandShow / HiRender / Kompass 的主交互仍是虚拟屏、网格、变形、融合带。够用折面和超长卷，球形要另接 mapping 模块或离线预畸变。

三思球形屏专利走「配置文件 → 经纬度非线性映射」。华院专利走「观察点 + 离轴投影矩阵 → 展开素材」。两者都说明：把普通 16:9 视频直接铺到球上，几何上就不成立。

04

三种 3D 不要混

行业话术里的「3D」至少是五件不同的事。曲面几何决定灯珠在空间的哪个位置；天空盒和穹顶决定贴上去的是一张 360 图还是鱼眼；裸眼立面是离线算好的一张图；眼镜双目是左右两张图；XR 是摄像机每帧重新算视锥。播控内核最后都落到按口输出的像素，差别在像素生成之前。

06

播出全链路

现有叙事停在服务器。现场撕缝经常出在处理器没进同一 house-sync，或发送卡「自己对齐」被当成 GPU 锁。点每一跳，看谁负责、常见翻车，并高亮矩阵与厂商卡。

点上面一跳。垂直整合解决配屏文件，不替代 Quadro 菊花链；Mosaic 拼桌面时 EDID/刷新不一致，同步组直接失败。

垂直整合 ≠ GPU 锁

诺瓦 Kompass / 卡莱特 GrandShow 可读发送卡连接关系文件，配屏快。这停在接收卡 hop。HiRender S3、Kommander F30、PIXERA four 写明的是 Quadro Sync II 菊花链，那是 GPU hop。

播控读连接关系，不能替代同步卡。发送卡「自己对齐」被当成帧锁，是现场最常见的误判。

NVIDIA Mosaic 把多口拼成超大桌面。各口 EDID 或刷新不一致时，Hardware Sync Group / Frame Lock 加不进去。Pandoras Box 帮助页把这件事写成：多 GPU Mosaic 必须上 Sync 卡。

处理器必须进 house-sync

Genlock 把多台设备的扫描相位锁到同一外部基准（BlackBurst / Bi-level / Tri-level）。它回答「何时开始扫这一帧」，不回答「这一拍是第几帧」。LED 现场 house-sync 必须同时进：播控机 NVIDIA Sync 卡 BNC、LED 处理器 Genlock IN（再 LOOP 到下一台）、摄像机 / 切换台（VP 路径）。

Brompton Tessera：从视频输入 genlock 到灯珠刷新；输入帧率与参考不一致会加倍或丢帧。诺瓦 MX40 Pro：Genlock IN/LOOP，Bi/Tri-level / Blackburst，最多约 20 台级联；低延迟与 Genlock 互斥。disguise：>1080p 不建议 BlackBurst。Sync 卡 BNC 若配成 TTL 输出，禁止再接发生器。

接线口诀：发生器 BNC 到各机 Genlock IN；处理器用 LOOP 级联；NVIDIA RJ45 只锁 GPU 集群，不要接到发生器或交换机。

13

开源项目

没有一个开源仓库等于完整的超分辨 LED 播控产品。有用的部分是：集群 present 屏障、穹顶播放、UV 工具。WebSocket 软同步明确标为精度不够。

14

LEDPlayControl 可抄的分层

不是产品愿景，是把上面对照完之后仍然成立的约束写成第一版架构。ST 2110 / PTP 明确不做，除非目标改成广播级 IP 输出。

  1. 播放时钟默认 NTP / 内部时码包。 超分辨拼接必须可叠加 NVIDIA Sync：Framelock 菊花链 + 可选外置 genlock + present barrier。软件对时不能冒充硬同步。
  2. 几何以 glTF/FBX + UV 为异形/球形主路径。 2D 多边形切片只保留给矩形和折面。观察点相机生成预畸变或实时投影，两种模式可切换。
  3. 切片按输出/GPU/节点生成。 离线烘焙稳、实时 mesh 投影活。切片清单与同步组名单分开配置。
  4. Director 默认不出画。 出画才进入硬件同步组。Backup 同步的是操作与工程，不是再拉一根 Sync 网到交换机上。
  5. 第一版不做 ST 2110 / PTP。 那是 L4。DP/HDMI 点对点先把 L1–L3 做对。
  6. 发送卡耦合做成适配器。 可以读诺瓦/卡莱特连接关系文件，但同步栈不绑死一家。

不从开源项目里抄错的东西

可借鉴 SGCT / Equalizer 的节点描述与 swap barrier，C-Play 的主从播放器结构，nDisplay 文档的 NVIDIA 接线。不要借鉴 Polycast 的 50–150 ms WebSocket 对时来开 LED 墙。MapMap / UV Studio 放在内容管线，不要当成播出内核。
